Agent factory for opencode

A coding agent that hands the work to specialists.

One command installs eleven subagents, forty workflow skills, and a delegation MCP server into your repository. The orchestrator writes the tickets, scopes each hand-off, and reads back the diff, so planning, implementation, review and commit are different agents with different permissions.

How it works

One session owns the conversation. The work moves out of it.

When a request needs real work, the orchestrator writes a ticket, hands it to a scoped child agent, and reads back only the diff and the hand-off — never another agent's whole transcript. Code, review and commit stay separate, so a reviewer can reject what an implementer produced.

  1. RouteClassify the request as a spike, a bounded ticket, or architecture, then pick the workflow.
  2. SpecifyArchitect turns intent into a spec and constraints; tickets are sliced until each is independently testable.
  3. ImplementSenior-dev builds a thin verifiable slice, leaving the tree dirty for review.
  4. ReviewQA runs the suite against the spec, scans for security issues, and flags over-engineering.
  5. LandGit-agent commits only what passed, with your review checkpoint in between.

The delegation server speaks to a warm opencode serve instance, detects v1 or v2, and resolves a model per agent with fallbacks — a stale provider name degrades the job instead of failing it.

Eleven do the work.

A single agent that plans, writes, reviews and commits is one opinion with write access. Splitting the roles costs a little coordination and buys a review you can actually trust.

The roster

Eleven agents, each with a narrow job and its own permissions.

  • orchestratorOwns the plan, delegates, reconciles the board.
  • architectTurns intent into a spec, constraints, and gated tickets.
  • challengerAttacks the plan before any code is written.
  • senior-devImplements tickets in thin, verifiable slices.
  • junior-devScoped boilerplate and helpers under supervision.
  • qa-engineerTests the diff against the spec; scans for security issues.
  • git-agentThe only writer to git; commits verified work, never pushes.
  • tech-writerDocs, ADRs, and retrospectives after a feature lands.
  • minimalism-enforcerFlags over-engineering and demands the simplest version.
  • devobsAudits Docker, CI pipelines, and deployment config.
  • visualizerFast UI mockups and accessible component templates.

Install

Node 22.18+, opencode installed, an empty afternoon.

Run it inside the project you want the factory in. Existing files are backed up and never clobbered; the MCP dependency install and its test run are part of the bootstrap. 

$ npx github:walidmoustafa2077/let-me-code

# then, in that project
$ opencode serve --port 4096   # terminal one
$ opencode                     # terminal two

Flags --yes--force--no-install--no-test--no-git--model <id>

The bootstrap installs the let-me-code command; run it again later to upgrade the factory in place.

On opencode v2 export OPENCODE_SERVER_PASSWORD before starting the server and the client; the two sides negotiate auth on their own.
